# 飞书导出素材解析与已有数据修复

来源：2026-09-18 用户截图及“我需要修复一下这个问题”。目标是使飞书导出素材可读，并使检索使用解码后的正文。普通 JSON、代码中的反斜杠、来源信息、结论引用及已删除素材受到保护。实现及本机数据修复已获本轮授权；本文件记录实现边界，不引入新的产品决策。

## 导入边界

`memory::evidence` 仍拥有文件和目录入库。新增同层 `lark_export` 解析器，只识别带 `ok` 和 `data.doc_id` 的文档导出响应，提取 `data.markdown` 并只解码一次 JSON。成功响应缺正文、失败的文档导出响应报错；其他 JSON 和转录走原有路径。

飞书的表格行、单元格转换成分行、竖线分列的可读文本，引用容器和高亮保留文字。代码围栏及行内代码中的标签保持原样。不执行 HTML，也不在展示层猜测性地替换反斜杠。

正文以临时文件交给现有上游导入能力，使用 `source_file_override` 保留真正来源。临时文件不写回源文件。切块、内容身份、嵌入、去重、存储仍由现有上游负责，不 fork 或 vendor 依赖。目录导入复用 `project_walk` 的忽略规则，调用同一文件入口；上游 0.9 的私有文件排除表需在本层保持等价，测试对照两条路径的计数。

## 已有数据边界

`src-tauri/examples/repair_lark_memory.rs` 是显式运行的维护工具，不随启动执行，不添加 CLI/MCP 公共合同。只接受调用者列出的来源路径和 schema 9。默认只读预览；写入必须给一个尚不存在的备份路径。

本机目标是 `corporate-action` 项目 `feishu_docs/corporate_action_wiki_downloads/` 中的以下四个 JSON：

- `01_option_customer_level_detail.json`
- `02_dividend_automation_unified_refactor.json`
- `03_ric_change_task_output.json`
- `04_equity_option_customer_detail_unified_display.json`

源文件已不存在。按原分块序号、100 字符重叠重建响应，并用原有 800/100 切块器核对逐块相等，再验证完整 JSON。任何缺块或不一致均中止。已删除块可用于核对原始编码边界，但不产生替代记录。每个活跃块只转换自身覆盖的正文范围，完整解码跨边界的转义和标签，不引入已删除块独有的正文。

无需转换的正文块保持原记录不变；内容变化产生新的内容寻址 ID，保留来源、项目、分块序号及其余元数据。重新生成向量后，新增正文及向量、旧记录软删除在一个 SQLite 事务内完成；FTS 由已有触发器同步。旧记录不覆写、不硬删除。空的接口包装块只软删除，不生成空素材。

写前以 SQLite `VACUUM INTO` 备份全库；事务内重新核对全部目标行快照及引用。目标被并发修改、新增引用、向量写入失败或 ID 与已删除记录冲突时回滚，不重试。已有结论的四类引用、知识卡引用、三元组来源或端点引用任一目标时中止，不自动重写证据链。重跑已完成的来源无变化。

## 验证

解析测试覆盖 Unicode、换行、表格、代码、空正文、非目标 JSON、失败响应及旧分块边界。入库测试覆盖文件、目录、来源保留、幂等、忽略规则与失败不写入。维护工具测试覆盖只读预览、正常替换、已删除素材、向量与 FTS、重跑、缺块、快照变化、新引用及中途失败回滚。实际写库前独立审查具体 diff；先在备份副本验证，再修复本机库并核对非目标行及结论保持一致。
